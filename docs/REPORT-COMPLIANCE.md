## 4. Где мы расходимся с новыми вводными — по существу

### 4.1. Скоринг в процентах

Сейчас: «балл 90.1» — число без интерпретации.

Нужно: процент + **уверенность** + **блокеры**, потому что 78% при данных по 4
из 6 критериев и 78% при данных по 6 из 6 — разные кандидаты.

Без этого приоритизация тоже невозможна: непонятно, что сравнивать.

### 4.2. Приоритизация

Сейчас отклики обрабатываются в порядке поступления. Это ломается на трёх вещах:

1. у hh.ru 500 платных просмотров резюме в день — квота уходит на слабых;
2. лимит «5 сообщений подряд» — писать всем сразу нельзя;
3. свежесть: ответ через сутки кандидат уже не ждёт.

Нужен предскоринг по метаданным (до открытия резюме) и очередь по приоритету с
учётом бюджета квоты. Подробно — в `docs/PLAN-SCORING.md`, раздел 3.

### 4.3. Настраиваемость при публикации

Сейчас критерии — поле вакансии, без версий и без экрана. «Сменить часть
вопросов при выкладке» требует, чтобы вопросы были **библиотекой с привязкой к
критериям**, а не текстом в промпте. Этого нет.

### 4.4. Не более 5 вопросов

Формально лимит есть (адаптер обрезает до 5), но это не логика:

- вопросы приходят одной пачкой, а не адаптивно;
- нет выбора по информационной ценности;
- нет раннего выхода, когда решение уже очевидно;
- нет стоп-правил (кроме одного — на повторный неясный ответ).

Пять вопросов «вообще» и пять вопросов «по делу» — разный результат по
конверсии ответа.
